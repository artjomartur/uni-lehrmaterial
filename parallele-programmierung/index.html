Dining Philosophers Simulator

Simulator initialisiert. (5 Philosophen)

Erklärung

Das Dining Philosophers Problem veranschaulicht Deadlocks und Ressourcenkonkurrenz. Jeder Philosoph (Kreis) benötigt zwei Gabeln (Linien), um zu essen. Klicken Sie auf "Nächster Schritt", um zufällige Aktionen auszuführen.

  • Gelb: Denkt nach
  • Blau: Wartet auf Gabel(n)
  • Grün: Isst
  • Rot: Deadlock (Alle haben eine Gabel und warten auf die zweite)

Aufgabe 1: Mutex vs Semaphore

Was ist der primäre Unterschied zwischen einem Mutex und einem binären Semaphor in Bezug auf das "Ownership"-Konzept?

Ein Mutex hat das Konzept des "Ownership" (Besitz). Nur der Thread, der den Mutex gesperrt hat (lock), darf ihn auch wieder entsperren (unlock). Ein Semaphor hingegen ist nur ein Zähler. Ein Thread kann ihn inkrementieren (post), während ein ganz anderer ihn dekrementiert (wait).

Aufgabe 2: Race Condition

Zwei Threads führen x = x + 1 aus. x ist anfangs 0. Welche Werte kann x nach Beendigung beider Threads annehmen und warum?

x kann 1 oder 2 sein.
Wenn beide Threads nacheinander ausführen, ist x=2.
Wenn Thread A den Wert 0 liest, dann Thread B den Wert 0 liest, B erhöht auf 1 und schreibt, dann A erhöht auf 1 und schreibt, ist das Ergebnis x=1 (Race Condition).

Aufgabe 3: Coffman-Bedingungen

Welche vier Bedingungen müssen gleichzeitig erfüllt sein, damit ein Deadlock auftreten kann?

1. Mutual Exclusion: Ressourcen sind nicht teilbar.
2. Hold and Wait: Ein Thread hält Ressourcen und fordert weitere an.
3. No Preemption: Ressourcen können nicht gewaltsam entzogen werden.
4. Circular Wait: Eine geschlossene Kette von Threads existiert, bei der jeder auf eine Ressource wartet, die der nächste hält.
